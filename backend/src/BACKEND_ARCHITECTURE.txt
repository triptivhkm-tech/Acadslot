1. HIGH-LEVEL ARCHITECTURAL OVERVIEW
================================================================================
AcadSlot is an academic slot booking and appointment scheduling backend. 
It follows a modular, layered Spring Boot architecture designed around clean
separation of concerns:

  [ Client Applications (Web / Mobile) ]
                  |
                  v  (HTTP / JSON + Bearer JWT)
  +--------------------------------------------------------------+
  |                   FILTER & INTERCEPTOR CHAIN                 |
  |  - RateLimitInterceptor (5 req/sec token bucket per IP)      |
  |  - SecurityFilterChain (CORS, CSRF disable, CSP Headers)     |
  |  - JwtAuthFilter (Bearer token validation, role resolution)   |
  +--------------------------------------------------------------+
                  |
                  v
  +--------------------------------------------------------------+
  |                     PRESENTATION LAYER                       |
  |  - Controllers: Auth, Admin, Student, Teacher, Notification   |
  |  - GlobalExceptionHandler (@RestControllerAdvice)             |
  +--------------------------------------------------------------+
                  |
                  v
  +--------------------------------------------------------------+
  |                     SERVICE / BUSINESS LAYER                 |
  |  - RequestAndApprovalService (Overlap check, rule validation)|
  |  - NotificationService (In-app notifications)                |
  +--------------------------------------------------------------+
                  |
                  v
  +--------------------------------------------------------------+
  |                     PERSISTENCE LAYER                        |
  |  - Spring Data JPA Repositories (PostgreSQL)                 |
  |  - Entities: User, Availability, Appointment, Request, etc.  |
  +--------------------------------------------------------------+

3. SECURITY, AUTHENTICATION & INTERCEPTORS
================================================================================
- Authentication Mechanism: Stateless JSON Web Tokens (JWT).
- Password Hashing: BCrypt (via BCryptPasswordEncoder).

A. SecurityConfig (com.acadslot.app.security.SecurityConfig)
   - Stateless Session Management: No HTTP sessions are stored on the server.
   - CSRF Disabled: Safe for stateless token-based REST APIs.
   - CORS Policy: Configured for the frontend origin (http://localhost:5173).
   - Security Headers:
     * Frame Options: DENY (prevents clickjacking attacks).
     * Content Security Policy: default-src 'self'.
   - Role-Based Authorization Hierarchy:
     * /api/auth/**      -> Public (Permit All)
     * /api/admin/**     -> Requires authority 'ROLE_ADMIN'
     * /api/teacher/**   -> Requires authority 'ROLE_TEACHER'
     * /api/student/**   -> Requires authority 'ROLE_STUDENT'
     * All other routes  -> Authenticated

B. JwtAuthFilter (com.acadslot.app.security.JwtAuthFilter)
   - Extends OncePerRequestFilter.
   - Intercepts requests with the 'Authorization: Bearer <token>' header.
   - Validates cryptographic signature via JwtUtil.
   - Populates Spring's SecurityContextHolder with UsernamePasswordAuthenticationToken.
   - Stores the parsed 'userId' into request attributes: request.setAttribute("userId", userId).

C. JwtUtil (com.acadslot.app.security.JwtUtil)
   - Uses HMAC-SHA256 (Keys.hmacShaKeyFor).
   - Token payload claims:
     * Subject: user.getEmail()
     * userId: user.getId()
     * role: "ROLE_" + user.getRole().name()
     * IssuedAt & Expiration (configured via jwt.expirationMs, default 24h)

D. RateLimitInterceptor (com.acadslot.app.security.RateLimitInterceptor)
   - Token Bucket algorithm (in-memory ConcurrentHashMap).
   - Limit: 5 requests per second per IP address.
   - Applied to /api/** endpoints.
   - Returns HTTP 429 Too Many Requests when exhausted.

6. BUSINESS LOGIC LAYER (SERVICES & VALIDATION RULES)
================================================================================

A. RequestAndApprovalService (com.acadslot.app.service.RequestAndApprovalService)
   Handles the appointment lifecycle, constraints, and overlap detection:

   1. submitRequest(student, availabilityId, reqStart, duration, reason):
      - Rule 4: Duration must be strictly greater than 0.
      - Rule 8: A student can only have ONE active request/appointment per teacher 
        (checks for existing PENDING or ACCEPTED requests).
      - Rule 5: Requested window [reqStart, reqStart + duration] must fit fully
        inside teacher's availability window [availability.startTime, availability.endTime].
      - Creates and persists AppointmentRequest with PENDING status.

   2. approveRequest(requestId, teacher):
      - Validates teacher is the actual owner of the request.
      - Ensures request is currently in PENDING status.
      - Rules 6 & 10 (Conflict / Overlap Detection):
        Retrieves all UPCOMING appointments for this teacher on the same date.
        Applies standard interval overlap formula:
          (newStart < existing.endTime) && (newEnd > existing.startTime)
        Throws RuntimeException if any conflict is detected.
      - Transitions request status to ACCEPTED.
      - Creates and saves a confirmed Appointment with UPCOMING status.
      - Triggers an automated notification to the student.

   3. rejectRequest(requestId, teacher):
      - Verifies teacher ownership.
      - Ensures status is PENDING.
      - Sets status to REJECTED.
      - Triggers an automated notification to the student.

   4. cancelAppointment(appointmentId, cancelReason, teacher):
      - Verifies teacher ownership.
      - Requires cancellation reason (non-empty string).
      - Transitions Appointment to CANCELLED and underlying Request to CANCELLED.
      - Triggers cancellation notification to the student with the reason.

B. NotificationService (com.acadslot.app.service.NotificationService)
   - createNotification(user, title, message, type): Creates and persists alerts.
   - markAsRead(notificationId, userId): Verifies ownership and flags as read.
   - getUserNotifications(userId): Fetches all user notifications ordered newest first.
